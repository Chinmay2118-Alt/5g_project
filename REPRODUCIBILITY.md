# Reproducibility guide — RAP-FedWMMSE (Group 12)

This guide explains how to install the project, where the data comes from, which parameters, seeds and
baseline settings were used, and the exact commands that regenerate every result, table and figure in the paper.

---

## 1. Requirements

| Item | Used for the reported results |
|---|---|
| OS | Windows 11 (64-bit). Linux and macOS should also work: the code is plain Python. |
| Python | 3.12.5 |
| Hardware | CPU only, no GPU needed. The final run used 12 cores. |
| Disk | About 2 GB for the virtual environment (PyTorch CPU build) |
| Packages | `requirements-lock.txt` gives the exact versions; `requirements.txt` gives minimum versions |
| Key versions | torch 2.14.0+cpu, numpy 2.5.4, scipy 1.18.1, cvxpy 1.9.3, clarabel 0.11.1, PySCIPOpt 6.3.0 (bundles the SCIP solver), matplotlib 3.11.2, PyYAML 6.0.3 |

## 2. Installation, step by step

Run from the folder that contains this file.

**Windows (PowerShell or Command Prompt)**
```bat
python -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements-lock.txt
```

**Linux / macOS**
```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-lock.txt
```

`requirements-lock.txt` already contains the PyTorch CPU index line. If an exact version is unavailable on your
platform, use `python -m pip install -r requirements.txt` instead.

**Check the installation** (from `rapfedbeam/`):
```bash
cd rapfedbeam
python -m pytest -q          # 87 tests, 2-5 minutes; all must pass
```

## 3. Data: synthetic, generated by the simulator

**No external dataset is used, and nothing needs to be downloaded.** All channel data is synthetic, generated
on the fly by `rapfedbeam/sim/` from the settings in `rapfedbeam/configs/config.yaml`:

- **Geometry:** a 500 m × 500 m area with 8 APs and 2 relays. Their positions are a *deployment*, seeded by
  (seed, deployment). 8 users are placed at random; one placement is a *drop*, seeded by (seed, deployment,
  drop).
- **Large-scale fading:** 3GPP UMi NLOS path loss −30.5 − 36.7 log₁₀(d/1 m) dB, minimum distance 10 m, 4 dB
  log-normal shadowing. round(0.3·K) = 2 of 8 users are blocked by an extra 25 dB.
- **Small-scale fading:** i.i.d. Rayleigh (complex Gaussian) per antenna.
- **Noise:** −174 dBm/Hz, 20 MHz, 7 dB noise figure. Channels are normalized so the noise variance is 1.
- **CSI:** perfect by default. In the aging sweep, Ĥ relates to H by H = ρĤ + √(1−ρ²)E, with E at each link's
  large-scale power.

**Seeds.**
- The global seed is **42** (`seed` in `config.yaml`). Each random quantity has its own stream, so sweep points
  differ only in the swept variable.
- **Evaluation:** drops 0–99, dealt round-robin to 10 deployments (drop d belongs to deployment d mod 10).
- **Training and validation:** drops with indices from 10⁶ and 2·10⁶, so they never coincide with evaluation
  drops.
- **Trained models:** trained per deployment and per sweep point, with PyTorch seeded per deployment.
- Serial and parallel runs give identical numbers.

**Self-supervised training needs no labels.** RAP-FedWMMSE learns by maximizing the network utility on simulated
channels.

## 4. Parameters and baseline configurations

All parameters are in `rapfedbeam/configs/config.yaml` and are also listed in Table I of the paper. The main
ones:

| Group | Values |
|---|---|
| Network | M = 8 APs, R = 2 relays, K = 8 UEs, N_A = N_R = 2 antennas, cluster L_c = 4, relay capacity 4, L_max = 1 |
| Power | 1 W per AP and relay (30 dBm); PA efficiency 0.4; circuit power 0.2 W |
| Objective | PF utility Σ ln(r_k + 10⁻³); λ_E = 0 (swept in the energy experiment) |
| QoS | R_min = 0.5 bit/s/Hz, outage tolerance 0.1 |
| Phase split | τ ∈ [0.2, 0.8]; fixed-τ baselines use 0.5; no-relay baseline uses 1 |
| RAP-FedWMMSE | L = 6 layers; 30 epochs × 4 local steps × 8 blocks; Adam, lr 3·10⁻³; soft-min κ = 10; prices η_Q = η_D = 0.2 (in-layer), 0.5 (per epoch); robust loss S = 4, ρ = 0.98, λ_O = 1; warm-up 3 epochs × 4 blocks per test drop |
| Association (Step 1) | α = (1, 1, 0.25, 1), threshold 0.5 |
| Federation | top-k 10 %, B_FL = 40,000 B, trigger 0.3, β = (1,1,1,1), A_max = 5, G_max = 1, kernel σ = 1, κ_AR = 0.3, ρ_p = 0.5 |
| Fronthaul | F_max = 1 Gbit/s per AP, F_ctrl = 10 Mbit/s per relay, T_e = 1 s |
| Models | adapter in→64→32, backbone 32→64→64→32 (8,352 parameters, the only federated part), head 2L+1+K outputs |

**Baseline configurations** (`rapfedbeam/docs/BASELINES.md` has the full details):

| Method | Configuration |
|---|---|
| Centralized WMMSE-SCA/AO | Full CSI; SCA with Clarabel via CVXPY; ≤ 100 iterations, tolerance 10⁻³; τ optimized per block |
| Centralized, no relay | The same without relays; τ = 1 |
| Local-WMMSE | 100 iterations of single-node WMMSE on own CSI; τ = 0.5 |
| RZF / MRT | Equal power; RZF regularization σ²/P_max; τ = 0.5 |
| Exact MINLP | SCIP spatial branch-and-bound; 2 APs, 1 relay, 2 UEs, 1 antenna; τ = 0.5; 1 % gap; 300 s limit |
| Ablations | FedAvg, no FL, untrained layers (η = 1, δ = 0.5, λ_reg = 1), plus the Deep Review diagnostic ablations |

## 5. Regenerating the results

All commands run from `rapfedbeam/`. Outputs go to `rapfedbeam/results/`.

### 5.1 Everything at once (the final run)

```bash
python run_experiments.py --drops 100 --deployments 10
```
- **What it does:** runs all 12 experiments and writes `results/<experiment>.json` plus the 14 figures to
  `results/figures/` (PNG, and a CSV of the plotted numbers).
- **Time:** about 3 hours on 12 cores. Uses all cores minus one by default; set it with `--workers N`.
- **Note:** the defaults are `--drops 50 --deployments 4`, so pass the values above to reproduce the paper.

### 5.2 Single experiments

```bash
python run_experiments.py --experiments <name> --drops 100 --deployments 10
```

| Figure / table in the paper | Experiment name(s) |
|---|---|
| Fig. 1 (G01) rate CDF, Fig. 2 (G02) outage, Fig. 12 (G12) FL curves, Table II (utility, rates, outage) | `baseline` |
| Fig. 3 (G03) rate vs power | `power` |
| Fig. 4 (G04) PF vs K, Fig. 11 (G11) runtime vs K | `num_ues` |
| Fig. 5 (G05) PF vs blockage | `blocked_fraction` |
| Fig. 6 (G06) PF vs relays (L_max = 1 and 2) | `num_relays`, `cooperation` |
| Fig. 7 (G07) PF vs fixed τ | `tau` |
| Fig. 8 (G08) PF vs channel aging | `aging` |
| Fig. 9 (G09) PF vs layers (reference lines come from `tau`) | `layers`, `tau` |
| Fig. 10 (G10) gap to the certified MINLP bound | `optimality_gap` |
| Fig. 13 (G13) energy trade-off (P_tot and time-averaged power) | `energy` |
| Fig. 14 (G14) FL under the fronthaul constraint | `fronthaul` |

**Redraw all figures from saved results** (no rerun, a few seconds):
```bash
python run_experiments.py --plot-only
```

### 5.3 Diagnostics added during Google Deep Review

These need the final-run results in `results/`, because each re-scores a published configuration as a
determinism check.

```bash
python -m diagnostics.round2 all      # about 20 min: ablations, zero-shot aging, starvation diagnosis
python -m diagnostics.round3 all      # about 30 min: tau-only split, K = 12 depth, SCIP fixed association,
                                      # pure-PF / no-outage training, untrained layers under aging
python -m diagnostics.runtime         # about 10 min: the clean timing of Table II (run on an idle machine)
```
Outputs go to `results/diagnostics/*.json`.

### 5.4 Every paired statistic quoted in the paper

```bash
python -m diagnostics.analysis all    # seconds; prints every number of Tables II-III and Sections VIII-A..J
```
- **Sub-sections:** `main` (Tables II and III, margins, aging tail, FL), `round2`, `round3` and `runtime`.
- **Format:** paired differences are printed as mean ± 1.96·std/√n over the same 100 drops, with the number of
  drops won.

### 5.5 Precomputed results

`rapfedbeam/results/` holds the raw per-drop JSON of the final run and of all diagnostics. It is not tracked in
git (it is generated by 5.1 and 5.3); the final-submission package includes it. With it, you can regenerate the
figures and every statistic **without** the 3-hour run:

```bash
python run_experiments.py --plot-only     # recreates results/figures/*.png and *.csv
python -m diagnostics.analysis all        # recreates every quoted number
```

The CSVs produced this way are identical to the committed ones in `rapfedbeam/figures/`.

## 7. What is and is not exactly reproducible

**Exactly reproducible** with the pinned versions:
- all utilities, rates, powers and statistics;
- the energy experiment, which was rerun once and reproduced every value exactly;
- each diagnostic, which re-scores a published configuration bit for bit before reporting anything new.

**Not exactly reproducible:**
- **Runtimes** depend on the machine and its load. Table II comes from one clean single-thread run; Fig. 11 was
  measured under parallel load.
- **Other environments:** a different BLAS or CPU, or other package versions, may change results in the last
  decimal places.

## 8. Troubleshooting

- **A worker is killed** (sleep, Task Manager): only the experiment in progress is lost. Rerun it with
  `--experiments <name>`, then `--plot-only`.
- **SCIP and PyTorch** must not share a process. The code runs SCIP in its own process automatically. Do not
  set `KMP_DUPLICATE_LIB_OK`.
- **Windows:** multiprocessing uses spawn, so run the commands from `rapfedbeam/` as shown.
